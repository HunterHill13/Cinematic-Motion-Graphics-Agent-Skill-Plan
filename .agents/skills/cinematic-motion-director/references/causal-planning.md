## 1. The Core Planning Law: Semantic Beat $\to$ Visual Job $\to$ Causal Graph

Before a single line of Remotion TSX is authored, the Director must formulate the **Causal Graph**.
A composition must behave as **ONE UNIFIED ORGANISM**, not a collection of independent animations.

### 1.1 The Seven Questions of Every Beat
For every meaningful narration beat in the Persian voiceover, answer:
1. **What is the narration doing?** (Introducing, contrasting, qualifying, counting, escalating, warning, concluding).
2. **What is the single primary visual job?** (e.g., *"Establish that the entry-level benchmark requires 65 points."*)
3. **Which existing visual element performs that job?** (The Primary Protagonist).
4. **Which existing element does it affect?** (Downstream target).
5. **What causes its appearance or transformation?** (Physical / narrative trigger).
6. **What consequence does it create?** (Force transfer, displacement, unlock).
7. **What element receives that consequence?** (Next downstream recipient).

## 2. The Mandatory "NO ORPHAN ELEMENT" Rule

**Every visible non-environmental graphic element MUST possess at least one explicit, documented relationship.**
If an element cannot trace its origin to a physical cause or its destination to a downstream consequence, **DELETE IT**.

### The 10 Allowed Relationship Types:

| Relationship Type | Definition | Physical / Cinematic Example |
|---|---|---|
| `CAUSE` | Direct physical initiator of a downstream action. | Column impact slams into base, compressing the foundation. |
| `CONSEQUENCE` | Physical result triggered by an upstream cause. | Shutter opens mechanically because the column reached its summit. |
| `TRANSFORMATION` | One physical entity alters its geometry or state into idea B. | A 2D baseline rule extrudes into a 3D structural plinth. |
| `BRIDGE` | Spatial or energetic connection linking two entities. | A rigid mechanical truss linking Column 1 to Column 2. |
| `SHARED_IDENTITY` | Sub-components belonging to the same mechanical body. | Plinth hydraulic accent cap moving locked with the plinth face. |
| `MATERIAL_REACTION` | Surface or lighting response to a physical event. | Contact shadow darkening and expanding as a column lands. |
| `SPATIAL_RELATION` | Alignment, containment, or geometric framing. | The foundation well that houses a hydraulic column. |
| `CAMERA_REVEAL` | Camera motion motivated specifically to expose this entity. | Camera cranes upward to follow the column's vertical surge. |
| `TYPOGRAPHIC_FORMATION`| Typography generated from physical world surfaces. | Numerals engraved into titanium and backlit by internal LEDs. |
| `INFORMATION_ENCODING` | A genuine data point required by the script. | The numeral "۱۱۰" representing the Ministry threshold. |

### Forbidden Justifications (Instant Reject):
- ❌ *"Adds cinematic atmosphere."*
- ❌ *"Fills empty space."*
- ❌ *"Prevents dead holds."*
- ❌ *"Looks like a high-tech HUD."*
- ❌ *"Adds energy to the scene."*

## 3. Element Budget Discipline

At any given frame, the screen must obey strict visual hierarchy:

```
┌─────────────────────────────────────────────────────────────┐
│  PRIMARY (Hero)          : Exactly 1 dominant visual job    │
│  SECONDARY (Support)     : 1–2 elements (cooperating)       │
│  TERTIARY (Detail)       : 0–2 elements (subordinate datum) │
│  NEGATIVE SPACE ANCHOR   : At least 1 completely clear      │
│                            quadrant preserved at all times  │
└─────────────────────────────────────────────────────────────┘
```

- **Group Limit:** No more than 3 subject groups active simultaneously. If a 4th group enters, a prior group must completely exit or be demoted into dark background context.
- **Single Hero Styling:** Only ONE element per frame may have hero styling (large scale, bright accent glow, high contrast). Competing hero elements create visual dissonance.
- **No Text Duplication:** On-screen text must never transcribe the spoken subtitle word-for-word. On-screen text is an architectural label ($\le 12$ words), not a teleprompter.

## 4. The Mandatory Question: "Who is it cooperating with?"

During design, implementation, and code review, every visual action must answer:
> **"Who is this action cooperating with?"**

### Examples:
- **Good:** Foundation pulse $\to$ Cooperates with Plinth 2 by delivering kinetic momentum from Plinth 1.
- **Good:** Camera push-in $\to$ Cooperates with Plinth 3 by tracking its upward vertical acceleration.
- **Good:** Shutter retraction $\to$ Cooperates with numeral "۶۵" by revealing it through physical inertia.
- **Bad:** Parabolic energy arc $\to$ Leaps through empty air without a physical cable or contact.
- **Bad:** Measurement tick marks $\to$ Sit static on the edge without calibrating or measuring anything.
- **Bad:** Telemetry timecode $\to$ Runs milliseconds unconnected to the educational narration.

## 6. The Independent Review Protocol & Removal Test

Before finalizing any composition or rendering master frames, run the **8-Point Adversarial Audit**:

1. **Semantic:** Does the visual transformation communicate the exact scientific/academic fact spoken in the voiceover?
2. **Causal:** What physical event caused this element to appear? What downstream effect does it trigger?
3. **Relational:** Who is this element cooperating with?
4. **Spatial:** Why is this element located here? Does it respect the empty quadrant?
5. **Motion:** Why is it moving? Does its easing profile reflect its physical mass?
6. **Hierarchy:** Is there exactly 1 dominant hero? Are secondary elements subordinate?
7. **Continuity:** Does this transition emerge organically from the prior state without a visual restart?
8. **The Removal Test (The Ultimate Filter):**
   > *"If this element or movement is removed from the composition, does the shot lose any narrative or scientific meaning?"*
   > - If **NO**: **DELETE IT IMMEDIATELY.**
